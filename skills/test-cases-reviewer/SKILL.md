# Test Cases Reviewer

对测试用例表（通常为 CSV）进行**模板符合性**、**FIT/DFX 场景归属**与**逐条 checklist 评审**，输出 Markdown 评审报告（含不通过/需整改条目与整改建议）。

## 强制参考（每次评审必须先读）

1. **[references/FIT与DFX场景归属判据.md](references/FIT与DFX场景归属判据.md)** — FIT/DFX 场景归属与跨表去重（评审 FIT、DFX 或全量时必读）
2. **[references/测试用例模板.md](references/测试用例模板.md)** — 16 列表头与列含义（openan 官方 15 列 + component_deps；备注列编排键约定）
3. **[references/测试用例评审checklist.md](references/测试用例评审checklist.md)** — 自检项、必须/建议分级与规则描述（**通用底线**，所有用例均适用）
4. **[references/特性级集成测试用例编写指导.md](references/特性级集成测试用例编写指导.md)** — FIT 专项字段与设计方法要求（**用例 type 为 FIT 时必读**）
5. **[references/DFX测试用例编写指导.md](references/DFX测试用例编写指导.md)** — DFX 专项字段与七类设计方法要求（**用例 type 为 DFX 类型时必读**）

**核心原则**（与 checklist 一致）：原子性、可重复性、可追溯性、完整性、独立性。

## 用例分类判定与编写指导选用

评审前须判定当前文件/用例适用的编写指导，再叠加 checklist 通用项进行逐条评审。

### 判定优先级

1. **用户显式声明**（对话中说明「评审 FIT 用例」「评审 DFX 用例」「全量测试用例」等）— 优先级最高
2. **文件名关键词**（见下表）
3. **表内「用例类型」列与备注 `DFX类型` 键**（解析 CSV 后，若各行类型一致可印证文件级判定；若混合则**按行**选用指导）
4. **均无法判定** → 视为该特性/组件的**全量测试用例**，**同时参考** FIT 与 DFX 两份编写指导

### 文件名关键词（大小写不敏感）

| 判定结果 | 文件名含以下信息时 |
|----------|------------------|
| **FIT** | `特性级集成测试`、`特性级集成测试用例`、`FIT`（且不含 `DFX`） |
| **DFX** | `DFX测试用例`、`DFX`、`_DFT_`、`_DFD_`、`_DFS_`、`_DFR_`、`_DFP_`、`_DFNS_`、`_DFC_` |
| **全量** | `总测试用例`、仅仓库/特性名而无类型标识（如 `Agent注册测试用例.csv`）、或其它无法归入 FIT/DFX 的命名 |

示例：

- `registry-center_Agent注册特性级集成测试用例.csv` → **FIT**
- `registry-center_Agent注册DFX测试用例.csv` → **DFX**（含 `DFX` 标识）
- `Agent注册测试用例.csv` → **全量**（无 FIT/DFX 标识）
- `Agent注册总测试用例表.csv` → **全量**
- 用户说明「这是 FIT 表」→ **FIT**（覆盖文件名）

### 按行选用（混合表）

同一 CSV 中若「用例类型」列/备注 `DFX类型` 键同时出现 FIT 类型（`功能测试`/`异常测试`/`协议测试`）与 DFX 类型（`可测试性测试`/`可诊断性测试`/`可运维性测试`/`可靠性测试`/`稳定性测试`/`性能测试`/`压力测试`/`安全测试`/`兼容性测试`，或备注含 `DFX类型:xxx`）：

- 文件级判定记为 **全量**
- **逐条评审**时：FIT 类型行对照 FIT 编写指导；DFX 类型行对照 DFX 编写指导；其它类型仅对照 checklist

### 报告中的记录

评审报告「评审概要」须写明：

- **文件级判定**：FIT / DFX / 全量
- **逐条适用指导**：若全量或混合，说明按行选用的规则
- **参考依据**：实际阅读并引用的 reference 文件列表

## 输入

| 输入 | 说明 |
|------|------|
| **测试用例文件**（必填） | CSV 或 Markdown 表格；用户指定路径 |
| **用例分类**（可选） | 用户声明 `FIT` / `DFX` / `全量`；未声明时按上文规则从文件名与表内「用例类型」推断 |
| **对照用例 CSV**（可选） | FIT+DFX 联评或编排层传入的对方产物；用于越界复核与跨表去重。评审 FIT 时传入 DFX CSV，评审 DFX 时传入 FIT CSV |
| **边界检查结论**（可选） | 编排层已产出的边界检查报告；须复核，越界/重复纳入必须项，不得忽略 |
| **目标里程碑/发布版本**（可选） | 用户给定版本时，校验各行「里程碑」列与该版本一致；未给定则不校验 |
| **需求/设计材料**（可选） | 特性提案、设计文档、需求列表；用于「需求覆盖」「场景覆盖」「DFX 覆盖」等文件级必须项 |
| **输出路径**（可选） | 未指定则写入 `outputs/<原文件名>-评审报告.md` |

无法读取文件或表头不符合模板时，在报告中说明并停止逐条评审。

## 模板符合性（评审前置）

表头必须为 **16 列**（openan 官方 15 列 + component_deps 第 5 列）、顺序一致：

```text
里程碑,用例名称,用例编号,模块,component_deps,需求链接,用例类型,优先级,前置条件,步骤描述,预期结果,可自动化,对应自动化用例,开发负责人,测试负责人,备注
```

表头唯一事实来源：`../test-cases-generator/templates/case-template.csv`。

生成侧要求 CSV 以 UTF-8 BOM（EF BB BF）开头（便于 Excel 正确显示中文）。校验表头时**先剥离文件头的 BOM 再比对**，不得仅因 BOM 存在判「模板不符合」。

| 检查项 | 级别 | 不符合时 |
|--------|------|----------|
| 列数为 15，列序与上表一致 | 必须 | 报告「模板不符合」，列出差异；不进入逐条 checklist |
| 每行数据列数与表头一致（CSV 多行单元格按规范解析） | 必须 | 标为结构错误行 |
| 文件名符合规范（见 checklist「测试用例文件名称规范」） | 必须 | 记入文件级不通过 |

文件名规则（与 checklist「测试用例文件名称规范」一致；版本段可省略）：

| 用例分类 | 规范格式 | 示例 |
|----------|----------|------|
| **FIT** | `[xx版本_]<目标仓库>_<特性>特性级集成测试用例` | `registry-center_Agent注册特性级集成测试用例` |
| **DFX** | `[xx版本_]<目标仓库>_<特性>DFX测试用例` | `registry-center_Agent注册DFX测试用例` |

须含仓库与特性信息；文件名判定为 FIT/DFX 时，后缀须与上表分类一致（全量表不适用单一后缀，按实际类型组合或用户声明处理）。

## 评审规则：必须 vs 建议

对照 [测试用例评审checklist.md](references/测试用例评审checklist.md) **逐项**检查每条用例（及文件级项）；再按**该行适用的编写指导**追加专项必须/建议项：

| checklist「要求」 | 评审结论 | 写入报告位置 |
|-------------------|----------|--------------|
| **必须** | 不符合 → **不通过** | 「不通过/需整改条目」 |
| **建议** | 不符合 → **整改建议**（用例仍可通过必须项时标为「通过（有建议）」） | 「整改建议」 |

同一用例可有多条必须项失败；建议项不单独判「不通过」，除非用户要求将建议视为硬性门槛。

### 评审范围排除（本 skill 不校验）

| 列 | 说明 |
|----|------|
| **备注**（编排键以外部分） | 校验点来源、材料差异、待确认项等自由文本；**逐条评审不检查其内容**，但备注中的**编排键**（`language_profile`/`protocol_primitive`/`执行策略`/`环境`/`DFX类型`）按 checklist「备注-必须」检查；**文件级 DFX 覆盖**分析时可读取不适用维度说明 |

**规则/依据列**：必须项失败时除写 `checklist` 外，若来自 FIT/DFX 编写指导，须写明 `特性级集成测试用例编写指导 §x` 或 `DFX测试用例编写指导 §x`。

### 必须项速查（逐条用例，除注明外）

| 属性 | 必须自检项要点 |
|------|----------------|
| 用例编号 | 仓库内唯一；仅中英数字、下划线、`-`，无空格与特殊字符 |
| 用例类型 | 类型准确（见下方 FIT/DFX 专项） |
| 模块 | 非空；与用例编号 feature 段一致 |
| component_deps | 非空；`none` 或 openan 仓名（多个用 `|` 分隔）；与步骤真实交互一致 |
| 用例名称 | 表达测试目的/意图；简洁明确、无二义 |
| 优先级 | P0–P2 填写合理（见 checklist 比例与定义） |
| 前置条件 | 写明环境/数据/系统状态；**环境要素明确化**（compose 服务、镜像版本、端口、token、测试数据等）；每步 `阿拉伯数字` + 分隔符（空格/`,`/`、`） |
| 步骤描述 | 逐步编号；可执行无歧义；需校验处标 `见结果N`；多个独立步骤不得共用一个序号；**末步为清理动作**（框架 §6.3） |
| 预期结果 | 逐步编号；禁止模糊二义表述；可客观判定（状态码、字段、日志、指标）；含清理步骤对应断言 |
| 可自动化 | P0/P1 必须为 `是`（框架 §8.1）；`是`/`否` 之外的取值不通过 |
| 备注编排键 | `language_profile` 非空且为 `python`/`java`/`js`/`shell` 之一；`protocol_primitive`（A2A-T 协议相关必须为四原语之一，纯 REST 用例为 `none`，不得为空或自造原语）；`执行策略` 为 `smoke`/`full`/`slow` 之一；`环境` 非空（框架 §6.4/§4.3.1，如 `docker-compose`、`with-workload-cluster`、`online`、`offline`） |

### FIT 专项（用例类型为 `功能测试`/`异常测试`/`协议测试` 时追加）

对照 [特性级集成测试用例编写指导.md](references/特性级集成测试用例编写指导.md) §2–§3：

| 属性 | 必须/建议 | 要点 |
|------|-----------|------|
| 用例类型 | 必须 | 为 `功能测试`/`异常测试`/`协议测试` 之一 |
| 用例编号 | 建议 | 推荐 `FIT-<feature>-<topic>-<3位序号>`，如 `FIT-registry-center-agentcard-001` |
| 前置条件 | 必须 | 同 checklist 必须项；FIT 场景下环境要素须具体到可复现（镜像版本、compose 服务、端口等） |
| 步骤/预期结果 | 必须 | 业务集成场景可执行；HTTP 状态码/响应字段等业务断言可客观判定；末步清理动作 |
| 场景归属 | 必须（语义） | 对照归属判据：禁止进程/容器自愈、资源不足降级、依赖故障恢复、探针/日志/指标/性能/安全/兼容专项；P2 不表示可含 DFX 用例 |

### DFX 专项（备注含 `DFX类型` 键 / 用例类型为 DFX 映射值时追加）

对照 [DFX测试用例编写指导.md](references/DFX测试用例编写指导.md) §2–§3：

| 属性 | 必须/建议 | 要点 |
|------|-----------|------|
| 备注 DFX类型 | 必须 | 为 DFT/DFD/DFS/DFR/DFP/DFNS/DFC 之一，且与「用例编号」中的 DFX 段一致 |
| 用例类型 | 必须 | 按 DFX 类型映射：`可测试性测试`/`可诊断性测试`/`可运维性测试`/`可靠性测试`/`稳定性测试`/`性能测试`/`压力测试`/`安全测试`/`兼容性测试` |
| 用例编号 | 建议 | 推荐 `DFX-<feature>-<topic>-<3位序号>`，如 `DFX-registry-center-agentcard-001` |
| 步骤描述 | 必须 | 含具体命令、接口路径、参数、观测窗口；禁止不可执行描述；末步清理动作（恢复配置、清除故障注入） |
| 预期结果 | 必须 | 含 HTTP 状态码、日志级别与关键字、指标名、health/metrics 端点字段等可客观判定项；禁止「正常」「无异常」 |
| 优先级 | 建议 | DFX 多为 P2；核心可观测/可运维验收可为 P0/P1，须在文件中分布合理 |
| 场景边界 | 必须（语义） | 对照归属判据：不重复 FIT 业务主路径；非法输入只断言可诊断性；配置变更只断言运维/可测试性机制；禁止以业务结果为唯一断言 |

### 全量表（同时参考 FIT + DFX 指导）

- 对 FIT 类型行应用 **FIT 专项**
- 对 DFX 类型行应用 **DFX 专项**
- 对其余「用例类型」行仅应用 checklist 通用项
- 文件级 **场景覆盖**：须同时审视功能/集成场景与非功能（DFX）维度是否匹配表中实际类型组合
- 文件级 **DFX 覆盖**（DFX 表或全量表中含 DFX 行时）：七类 DFX 维度（DFT/DFD/DFS/DFR/DFP/DFNS/DFC）中，**所有适用维度**须有对应用例；不适用的维度须在备注、覆盖说明或需求/设计材料中说明原因

### 建议项速查（写入整改建议，不单独判不通过）

- 用例名称：≤50 字；动宾（补）短语；可用 `_` 追加条件
- 用例编号：编号连续、feature 段全表一致
- 优先级：整体 P0/P1/P2 占比合理
- 前置条件：不含登录/调用等操作步骤；≤10 步
- 步骤描述：写明入口与参数；≤10 步
- 预期结果：编号与步骤对应；多步骤时标明对应关系；描述具体可观察
- 备注：复杂场景建议在备注中标注所用设计方法；用户给了里程碑建议填入「里程碑」列便于追溯

### 文件级必须项（整表一次）

| 项 | 要点 |
|----|------|
| 需求覆盖 | 有需求材料时：用例覆盖全部功能点，无理解偏差 |
| 场景覆盖 | 含正常/异常/交互；DFX 维度与用例类型匹配（全量表须覆盖表中出现的 FIT 与 DFX 类型；无材料则记「未校验，缺需求输入」） |
| 场景归属 | 对照 [FIT与DFX场景归属判据.md](references/FIT与DFX场景归属判据.md)：本表越界用例 → 不通过（第 3 节，用例编号填具体编号，问题属性填「场景归属」） |
| 跨表去重 | 提供了对照 CSV 时：同一触发 + 同一断言焦点出现在两表 → 不通过（双方编号均列出）；无对照 CSV 记「未校验，无对照 CSV」。合法并存（断言焦点不同）不构成不通过 |
| DFX 覆盖 | DFX 表或全量表含 DFX 行时：七类 DFX 维度（DFT/DFD/DFS/DFR/DFP/DFNS/DFC）中，所有**适用**维度须有对应用例；不适用的维度须说明原因（可在 notes、报告或设计材料中）；仅覆盖部分适用维度或未说明不适用原因 → 不通过；无设计/需求材料判定适用维度时记「未校验，缺特性设计材料」 |

## 评审流程

1. **阅读** `FIT与DFX场景归属判据.md`、`测试用例模板.md`、`测试用例评审checklist.md`；按分类判定结果再读 FIT 和/或 DFX 编写指导。
2. **判定用例分类**：用户声明 → 文件名 → 表内「用例类型」/备注 `DFX类型` 键分布；记录文件级 FIT / DFX / 全量。
3. **解析** 用户指定的用例文件（CSV 注意引号内换行）；若提供对照 CSV 则一并解析。
4. **模板校验**：表头、列数、文件名。
5. **文件级评审**：文件名规范；若用户提供需求材料，做覆盖度分析（全量表分别审视功能与非功能覆盖）；DFX 表或含 DFX 行的全量表须做 **DFX 维度覆盖**检查（七类维度适用性、不适用原因）。
6. **场景归属与跨表去重**（必须项）：对照归属判据检查本表越界；有对照 CSV 时检查跨表重复；若传入边界检查结论则复核，遗漏的越界/重复仍记不通过。
7. **逐条评审**：对每一行用例，先 checklist 必须项（含备注编排键 `language_profile`/`protocol_primitive`/`执行策略`/`环境` 与第 5 列 `component_deps`），再按该行类型追加 FIT/DFX 专项；记录失败项与证据（引用原文片段）。
8. **编号唯一性**：扫描全表「用例编号」列重复项，重复者全部标不通过。
9. **建议项扫描**：汇总 checklist 与 FIT/DFX 指导中的建议类问题。
10. **生成报告**：按下方 Markdown 模板写入文件，并在对话中给出摘要。

## 输出：Markdown 评审报告

**必须**将完整报告写入 `.md` 文件（用户指定路径或默认 `outputs/`）。

```markdown
# 测试用例评审报告

## 1. 评审概要

| 项目 | 内容 |
|------|------|
| 评审文件 | `<路径>` |
| 对照用例 CSV | `<路径或「无」>` |
| 用例分类判定 | FIT / DFX / 全量（及判定依据：用户声明 / 文件名 / 表内用例类型） |
| 目标里程碑 | `<版本或「未指定」>` |
| 用例总数 | N |
| 通过（仅必须项） | X |
| 不通过 | Y |
```

## 判定细则（评审时统一执行）

**用例编号**

- 允许：中文、英文、数字、`_`、`-`
- 不允许：空格、`#`、`/`、括号等其它特殊字符
- 全表重复 → 每条涉及编号均不通过
- FIT 行：编号符合 `FIT-<feature>-<topic>-<3位序号>` 为建议符合；DFX 行：编号符合 `DFX-<feature>-<topic>-<3位序号>` 为建议符合

**前置条件 / 步骤描述 / 预期结果 序号**

- 合格分隔符：`1、` `1,` `1 ` `1.`（预期结果常用 `1.`）
- 不合格：无序号、仅破折号列表、多级 `1.1` 若无规范说明

**步骤描述与预期结果**

- 步骤含「验证」「检查」且无 `见结果N` → 步骤描述必须项不通过
- 单序号内用分号串联多个独立操作 → 不通过
- **末步非清理动作**（未删除本用例创建的测试数据/服务、未恢复被修改配置或故障注入）→ 步骤描述必须项不通过（框架 §6.3）
- 预期含「正常」「成功」「符合预期」等不可客观判定用语 → 预期结果必须项不通过
- **DFX 行**：预期缺少可核对的状态码/字段/日志/指标 → 预期结果必须项不通过（DFX 编写指导 §3）

**component_deps 独立列与备注编排键（language_profile / protocol_primitive / 执行策略 / 环境 / DFX类型）**

- 备注缺 `language_profile` 键，或其值不在 python/java/js/shell 枚举内 → 必须项不通过
- `component_deps` 列为空，或填了非 openan 仓名（含 owner 前缀、明显拼写错误）→ 必须项不通过
- 备注缺 `protocol_primitive` 键 → 必须项不通过；涉及 A2A-T 步骤（步骤中出现 Task-T/Notification-T/Negotiation-T/Authorization-T 或 A2A-T SDK 调用）但填 `none` → 必须项不通过；自造原语名 → 必须项不通过
- 备注缺 `环境` 键或值为空（框架 §6.4/§4.3.1 要求标注环境） → 必须项不通过
- 备注缺 `执行策略` 键，或其值不在 smoke/full/slow 枚举内 → 必须项不通过
- DFX 行备注缺 `DFX类型` 键，或其值不在 DFT/DFD/DFS/DFR/DFP/DFNS/DFC 枚举内，或与用例编号中的 DFX 段不一致 → 必须项不通过

**可自动化**

- P0/P1 行「可自动化」非 `是` → 必须项不通过（框架 §8.1）
- 取值非 `是`/`否` → 必须项不通过；P2 为 `否` 且备注未说明原因 → 整改建议

**里程碑（可选标注）**

- 用户给定目标版本：「里程碑」列填写且版本与目标不一致 → 不通过
- 用户未给定目标版本：不校验里程碑标注有无

**需求链接**

- 需求材料中含需求/Issue/PR 链接，而整列留空 → 整改建议；材料中亦无链接时允许留空，记入评审说明

**场景归属与跨表去重（必须项）**

- 先读 [FIT与DFX场景归属判据.md](references/FIT与DFX场景归属判据.md)
- FIT 行验证目标为探针/日志/指标/自愈/性能/安全/兼容 → 场景归属必须项不通过（依据：归属判据 §2–§4）
- DFX 行以业务主路径/功能配置生效/业务负例拒绝为唯一断言、无非功能断言 → 场景归属必须项不通过（依据：归属判据 §3–§4）
- 有对照 CSV：触发相同且断言焦点相同 → 跨表去重必须项不通过（第 3 节列出双方编号）
- 传入了编排层边界检查结论：必须复核；结论中的越界/重复若本报告未收录 → 补记为不通过
- 合法并存（断言焦点不同）不判不通过

**文件名（文件级）**

- 文件级判定为 **FIT** 时，文件名应匹配 `*特性级集成测试用例` 模式（见 checklist 规范表）→ 不符记入文件级不通过
- 文件级判定为 **DFX** 时，文件名应匹配 `*DFX测试用例` 或含明确 DFX 类型标识 → 不符记入文件级不通过
- 文件级判定为 **全量** 时，不强制单一后缀，但须含仓库与特性信息

**precondition**

- 仅写笼统环境描述、未明确关键环境要素（compose 服务、镜像版本、端口、网络/权限等）→ precondition 必须项不通过（checklist 环境要素明确化）

**DFX 覆盖（文件级）**

- 文件级判定为 **DFX** 或 **全量**且表中含 DFX 行时，须检查七类 DFX 维度（DFT/DFD/DFS/DFR/DFP/DFNS/DFC）覆盖情况
- 从备注 `DFX类型` 键、用例编号中的 DFX 段归纳已覆盖维度
- 有设计/需求材料时：判定各维度是否适用；适用但未覆盖 → 文件级不通过（记入第 3 节，用例编号填 `—（文件级）`）
- 不适用维度无原因说明（备注、报告说明或设计材料均无）→ 文件级不通过
- 无材料判定适用维度 → 记「未校验，缺特性设计材料」，不强行判不通过

**用例类型（FIT/DFX 专项）**

- FIT 行「用例类型」非 `功能测试`/`异常测试`/`协议测试` → 用例类型必须项不通过
- DFX 行「用例类型」非 DFX 映射值（`可测试性测试`/`可诊断性测试`/`可运维性测试`/`可靠性测试`/`稳定性测试`/`性能测试`/`压力测试`/`安全测试`/`兼容性测试`），或备注 `DFX类型` 键缺失/非法/与编号段不一致 → 必须项不通过
- **不评审**备注列编排键以外的自由文本（见上文「评审范围排除」）
