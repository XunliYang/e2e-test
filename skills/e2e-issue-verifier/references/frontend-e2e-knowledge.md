# 前端组件 E2E 排查领域知识库

本知识库作为 `e2e-issue-verifier` 的领域知识支撑，用于前端 Playwright 失败分析时校准真实 DOM 结构、复合控件交互链路、虚拟列表行为和常见定位歧义。

它不是流程文档；流程由 `SKILL.md` 负责。本文件只回答一件事：**遇到前端复合控件失败时，应该如何基于 DOM 结构做更通用、更可执行的诊断。**

## 与 `SKILL.md` 的调用关系

### `SKILL.md` 负责什么

`SKILL.md` 负责：
- 识别前端 / 后端验证路径
- 生成最小验证命令
- 接管 trace、日志、report、Issue 评论等证据
- 输出根因、修复状态、FixContext、交接建议
- 控制是否交给 `github-issue-fixer` 或 `github-issue-creator`

### 本知识库负责什么

本知识库负责：
- 解释前端复合控件的真实 DOM 结构
- 约束分析时的证据优先级
- 定义隐藏实例、错误容器、虚拟列表、瞬态遮挡等通用判定规则
- 提供更稳定的定位锚点优先级
- 把“看起来像 timeout”的问题拆成可验证的结构性原因

### 使用方式

当 `SKILL.md` 分析前端失败时，必须主动参考本知识库，特别是：
- 下拉 / 版本选择器 / 菜单 / 弹层
- 虚拟列表 / 懒加载列表
- 同名节点、隐藏节点、旧实例残留
- 动画、遮挡、过渡态

如果本知识库能解释当前 DOM 结构，则优先按本知识库的规则定位；如果不能解释，则回到 trace、截图、DOM 快照继续补证据，而不是直接扩大 timeout。

## 0. 通用诊断原则

当测试失败涉及复合控件时，必须按以下顺序排查：

1. 先判断是否命中隐藏实例、旧弹层残留或零尺寸节点
2. 再判断是否命中错误容器或错误弹层实例
3. 再判断是否存在同名节点歧义
4. 再判断目标项是否位于虚拟列表当前可视窗口
5. 再判断是否存在瞬态遮挡或动画未完结
6. 最后才考虑等待不足或 selector 过宽

在未排除上述结构性问题前，不得直接把失败归因为页面加载慢、timeout 不足或需要单纯增加 sleep。

## 1. Select / Dropdown / Popover / Modal 的通用特征

### 1.1 DOM 挂载机制

- 复合控件的弹层通常不是挂在业务表单节点内部，而是挂载到页面根节点或 `body` 下。
- 这意味着父子层级选择器往往不可靠，必须先找到当前激活的弹层容器，再在容器内找目标项。

### 1.2 隐藏实例与旧实例残留

- 页面关闭弹层后，DOM 可能不会立刻移除，而是保留一个隐藏实例。
- 隐藏实例常伴随以下特征之一：
  - `*-hidden` 类名
  - `pointer-events: none`
  - 零尺寸或接近零尺寸
  - `aria-hidden` / 非激活状态
- 若存在多个同名实例，`first()` / `last()` 容易命中错误对象。

### 1.3 诊断规则

当看到上述特征时，应优先判断：
- 当前 locator 是否误命中了隐藏实例
- 当前 option 是否属于错误弹层
- 页面是否存在旧弹层残留干扰

### 1.4 推荐定位策略

优先顺序：
1. 当前激活容器内的节点
2. `data-*` / `title` / `aria-label`
3. `role` + 可见性限定
4. 纯文本

尽量避免仅用全局文本匹配直接点击同名节点。

---

## 2. 虚拟列表 / 懒加载列表（Virtual List / rc-virtual-list）

### 2.1 延迟渲染特征

- 长列表、版本选择器、下拉选项集常采用虚拟滚动。
- 虚拟列表只保证当前可视区内的节点真实存在于 DOM 中。
- 不在当前窗口内的选项，可能根本不存在，或者只在准备容器里存在零尺寸结构。

### 2.2 诊断规则

如果 trace 或 DOM 显示：
- 下拉已经打开
- 目标项文本存在于候选列表中
- 但脚本始终找不到对应选项

则优先检查：
- 是否需要滚动虚拟列表承载器
- 是否滚动了错误的容器
- 是否 locator 命中了隐藏实例而不是当前窗口

### 2.3 推荐滚动对象

优先滚动：
- `rc-virtual-list-holder`
- 实际带 `overflow-y: auto` 的列表承载器

不要默认滚动整个页面，也不要默认扩大 timeout。

### 2.4 推荐操作顺序

1. 打开弹层
2. 找到当前激活容器
3. 确认目标项在可视窗口内
4. 必要时滚动承载器
5. 找到后再点击

## 3. 动画、遮挡与过渡态

### 3.1 瞬态遮挡

- 页面切换、加载、提交、弹层展开时，可能出现 Loading、Toast、骨架屏等临时遮挡。
- 这种情况可能导致点击被拦截，但通常不是根因，只是时序现象。

### 3.2 动画未完结

- 弹层、菜单、下拉展开时可能处于淡入、缩放或位移动画中。
- 动画未结束时，元素可能还没进入可交互状态，`pointer-events` 仍可能不可用。

### 3.3 诊断规则

如果失败发生在刚打开控件、刚切换页面、刚提交动作之后，应优先判断：
- 是否存在遮挡层
- 是否处于动画过渡态
- 是否真的进入了稳定可交互状态

只有在排除这些因素后，才考虑调整等待或重试策略。

## 4. 版本选择器与复合下拉的通用分析原则

### 4.1 不要先假设“版本不存在”

版本号存在、但定位失败，通常不代表数据缺失，而更可能是：
- 命中隐藏实例
- 命中错误容器
- 虚拟列表未滚动到该项
- 使用了不稳定的文本锚点

### 4.2 常见稳定锚点

对于版本选择、菜单项、弹层项，优先考虑：
- `title`
- `aria-label`
- `data-*`
- 当前激活容器内部的 `role` 节点

纯文本可作为补充，但不应作为唯一锚点。

### 4.3 版本选择器的结构判断

若页面 DOM 同时存在：
- 隐藏的 dropdown 容器
- 当前激活的 dropdown 容器
- 虚拟列表承载器

则必须先识别当前激活容器，再在其内部寻找目标版本。

## 5. 复合控件通用诊断清单

当失败涉及下列控件时，必须走下面的诊断清单：
- 下拉框 / 选择器
- 弹窗 / 对话框
- 菜单 / 菜单项
- 标签页 / tab
- 虚拟列表 / 分页列表
- 回滚 / 升级 / 版本切换面板

### 5.1 必查项

- 是否存在隐藏实例
- 是否存在激活实例
- 是否有多个同名节点
- 是否是虚拟列表
- 目标项是否只在属性中稳定暴露
- 是否需要限定到当前 popup/container
- 是否存在动画 / 遮挡 / 过渡态

### 5.2 结论分类

通常可以归为以下几类：
- 隐藏实例误命中
- 错误容器误命中
- 同名节点歧义
- 虚拟窗口遗漏
- 瞬态遮挡
- 动画未稳定
- 文本锚点不稳定
- 交互链路不完整

---

## 6. 诊断优先级与禁忌

### 6.1 优先级

1. 可见性与激活容器
2. DOM 结构歧义
3. 虚拟列表可视窗口
4. 稳定锚点（title / aria-label / data-*）
5. 最后才是 timeout / retry / scroll 距离微调

### 6.2 禁忌

- 禁止在存在隐藏实例时直接 `.first()` 就点击
- 禁止在未确认激活容器前使用全局文本点击
- 禁止在虚拟列表场景默认扩大 timeout 作为首选修复
- 禁止把所有失败都归因于页面加载慢

---

## 7. 与 `e2e-issue-verifier` 的配合方式

### 7.1 `SKILL.md` 应该先做什么

- 读取失败日志、trace、report、Issue 评论
- 生成最小验证命令
- 判断属于前端还是后端
- 收敛到最小用例/文件
- 输出根因、FixContext、修复状态建议

### 7.2 本知识库应当提供什么

- 为什么这个 locator 会误命中
- 为什么这个容器不是当前激活实例
- 为什么目标项需要滚动虚拟列表
- 为什么 `title` / `aria-label` 比纯文本稳定
- 何时应判定为结构性问题而不是简单的等待问题

### 7.3 分工边界

- `SKILL.md` 负责流程、交接、验证、结论
- 本知识库负责前端 DOM / 组件库行为的诊断规则

如果本知识库已经给出了明确规则，`SKILL.md` 应优先按这些规则解释 DOM，再决定是否需要修改代码、交接或验证。

---

## 8. 适用范围

本知识库主要适用于 openAN 前端 e2e 场景中的以下 DOM 模式：
- 下拉选择器
- 版本切换器
- 虚拟列表
- 弹层 / 对话框
- 菜单 / tab / 回滚面板
- 具有隐藏实例和激活实例并存的复合控件

当页面结构明显不属于上述模式时，应回到通用 DOM/trace 分析，不要机械套用本知识库。
