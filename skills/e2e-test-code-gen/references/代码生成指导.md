# 测试代码生成指导

## 1. 定位

将**评审用例 CSV**（openan 16 列用例表 = 官方 15 列 + component_deps 独立列，编排键在备注列）按备注 `language_profile` 键分组转为目标仓库可运行的测试代码。

**输入**：评审 CSV + 已确认的 `tests/README.md`。
**输出**：目标仓测试目录源码（python `tests/`；java `src/test/java`；js `tests/e2e` 等；shell `tests/*.bats`）。

## 2. 通用规则（四语言共用）

1. **用例编号必落代码**：每个测试用例都可被用例编号检索（docstring / `@DisplayName` / `test()` 标题 / `@test` 名）
2. **步骤描述 ↔ 预期结果对齐**：步骤中 `见结果N` 处必须插入对应编号断言；禁止「只走步骤不断言」；末步清理动作实现为 teardown/清理步骤
3. **DFX 用例断言非功能观测点**：日志级别+关键字、metrics/health 端点字段、进程/容器状态；禁止以业务结果为唯一断言
4. **协议用例用 SDK**：备注 `protocol_primitive` ≠ none 时用 A2A-T SDK 编排；互操作样本数据用 `a2a-t-corpus` 既有目录，禁止两份 SDK 各自维护
5. **环境走变量**：服务地址、token 等一律环境变量 + `.env.template`，禁止硬编码
6. **对齐目标仓既有风格**：生成前先读该仓既有测试文件，import 顺序、fixture 风格、断言库以既有为准
7. **文件头注明来源**：来源 CSV 路径 + 本文件覆盖的用例编号列表

## 3. Python（pytest）

详见 [python.md](python.md)。要点：

- e2e 层：环境变量（如 `REGISTRY_CENTER_URL`）连已启动服务；未设置则 `skipif` 跳过，禁止报错
- integration 层：`httpx.ASGITransport` 进程内直连，无需起服务
- 异步用例必加 `@pytest.mark.asyncio`
- DFX 观测：用 `caplog` 断言日志级别/关键字，或请求 `/health`、`/metrics`

```python
@pytest.mark.e2e
async def test_restart_data_persisted(client):
    """DFX-registry-center-service-restart-001: registry-center 进程重启后已注册 Agent 数据保持"""
    ...  # restart via compose, then assert agents retrievable
    assert resp.status_code == 200
```

运行：`uv run pytest tests/e2e -m e2e -q`；按用例：`uv run pytest tests/e2e -q -k "fit_registry_center_agentcard_001 or dfx_registry_center_service_restart_001"`。

## 4. Java（JUnit5）

详见 [java.md](java.md)。要点：

- 契约/协议测试用 `@WireMockTest` 模拟对端；类名 `_<Protocol>ContractTest`
- integration 类 `_<Flow>IT` 由 Failsafe 接管（`mvn verify`）
- DFX 观测：捕获日志（Logback ListAppender）或断言 Actuator/health 端点

```java
@Test
@DisplayName("DFX-registry-center-service-restart-001: 服务重启后已注册 Agent 数据保持")
void should_keep_agents_after_restart() { ... }
```

运行：`mvn test -Dtest=AgentRegisterContractTest`；integration：`mvn verify`。

## 5. JS/TS（Vitest + Playwright）

详见 [js.md](js.md)。要点：

- 组件/单测用 Vitest + MSW；页面 E2E 用 Playwright
- Playwright 用例 ID 写在 `test()` 标题；baseURL 走环境变量
- 失败保留截图/trace：`screenshot: 'only-on-failure'`
- DFX 观测：页面日志面板断言，或 API 轮询 `/health`

```ts
test('FIT-marketplace-agentcard-001: 登录后展示 Agent 市场', async ({ page }) => {
  await page.goto('/')
  await expect(page.getByRole('link', { name: 'Agent Market' })).toBeVisible()
})
```

运行：`npx playwright test --grep "FIT-marketplace-agentcard-001"`；Vitest：`npm run test`。

## 6. Shell（bats）

详见 [shell.md](shell.md)。要点：

- 每个用例独立 setup/teardown，临时目录隔离（`mktemp -d`，隔离 `$HOME`）
- 被测脚本绝对路径调用；docker 场景不可用时 `skip`
- DFX 观测：`docker logs` / `docker inspect` 断言日志关键字与容器状态

```bash
@test "DFX-ofpower-install-invalid-input-001: installer 异常输入打印错误并以非零退出" {
    run "$BATS_TEST_DIRNAME/../../binary/installer.sh" --invalid-flag
    [ "$status" -ne 0 ]
    [[ "$output" == *"invalid"* ]]
}
```

运行：`bats tests/`；静态检查：`shellcheck tests/ && shfmt -d .`。

## 7. 最小验证（交付前必跑）

| profile | 验证命令 |
|---------|----------|
| python | `uv run pytest --collect-only -q` + `uv run ruff check tests/` |
| java | `mvn -q test-compile` |
| js | `npx vitest run --reporter=dot`（无收集错误） |
| shell | `bats --count tests/` + `shellcheck tests/` |

验证失败先修生成代码（或报告目标仓环境问题），不得带错交付。
