# Test Cases Generator（全流程编排）

串联 **特性级集成测试用例生成**、**DFX 测试用例生成**、**FIT/DFX 边界检查与去重** 与 **测试用例评审**，形成「生成/修改 → 边界检查 → 评审 → 不通过则按报告修改」闭环。本 skill **不自行编写用例细则**，必须通过读取并执行子 skill 完成生成与评审；边界检查对照本目录归属判据执行。

## 子 Skill 路径（必须读取后执行）

| 步骤 | Skill | 路径 |
|------|-------|------|
| FIT 生成/修改 | feature-level-test-cases-gen | [../feature-level-test-cases-gen/SKILL.md](../feature-level-test-cases-gen/SKILL.md) |
| DFX 生成/修改 | dfx-test-cases-gen | [../dfx-test-cases-gen/SKILL.md](../dfx-test-cases-gen/SKILL.md) |
| 用例评审 | test-cases-reviewer | [../test-cases-reviewer/SKILL.md](../test-cases-reviewer/SKILL.md) |
| FIT/DFX 边界检查 | （本 skill 执行） | [references/FIT与DFX场景归属判据.md](references/FIT与DFX场景归属判据.md) |

调用某子 skill 前：**先用 Read 工具完整阅读其 `SKILL.md`**，再按其「执行指令」与输入/输出约定操作；禁止跳过子 skill 的强制 reference 阅读与质量自检。边界检查前必须先读本目录归属判据。

## 流程总览

```text
用户输入（材料 + 生成范围 + 必填元数据）
        │
        ▼
┌──────────────── epoch = 1..3 ────────────────┐
│  1. 生成（epoch=1）或按评审报告修改（epoch>1） │
│     → 写入中间产物 CSV（带 epoch-N 后缀）      │
│  2. FIT/DFX 边界检查与去重                     │
│     → 写入中间产物边界检查报告                  │
│  3. 调用评审 skill（互传对方 CSV 与边界结论）   │
│     → 写入中间产物评审报告                     │
│  4. 判定：评审必须项 + 边界检查均通过 → 跳出；  │
│     否则 epoch++（epoch 已达 3 则无论结果均终止）│
└──────────────────────────────────────────────┘
        │
        ▼
交付最终 CSV + 末轮评审报告 + 边界检查报告 + 全流程摘要
```

**硬性上限**：全流程最多 **3 轮**（`epoch-1` … `epoch-3`）。第 3 轮评审结束后**必须终止**，即使仍为不通过。

## 输入

| 输入 | 说明 |
|------|------|
| **特性材料（至少其一，必填）** | 提案、设计、接口/API 文档、用户手册、目标仓库源码、既有 FIT 等；无材料则停止并提示补充 |
| **生成范围（必填意向）** | `FIT` / `DFX` / `FIT+DFX`；用户未明示时根据诉求推断，无法推断则询问后再继续 |
| **特性/模块名称（必填）** | 透传给子 skill 写入 `module` 列与文件命名；缺失则停止，禁止从材料推断 |
| 目标仓库（可选） | 用于默认文件命名前缀（`<目标仓库>_<特性名称>…`）与源码定位；未给则命名不含该段 |
| 里程碑（可选） | 用户指定版本（如 `v1.0`）时透传，子 skill 将其写入 notes `里程碑:v1.0`；未指定则不写 |
| 既有 FIT CSV | **透传**给 DFX 子 skill 做交叉去重；未指定则按子 skill 规则留空 |
| 需求/设计材料（评审用） | 可选；透传给 reviewer 做文件级覆盖分析 |
| **最终输出路径** | 可选；分别指定 FIT/DFX 最终 CSV 路径。未指定则基名为 `[<目标仓库>_]<特性名称>特性级集成测试用例` / `[<目标仓库>_]<特性名称>DFX测试用例`（**不含** `epoch-` 后缀） |
| **中间产物目录** | 可选；未指定则为项目根目录下 `intermediate/`（不存在则新建） |

用户指定的最终路径与中间目录可为相对路径（相对项目根）或绝对路径。

**硬性门禁**：上表标为必填的项（特性材料、生成范围、特性/模块名称）**缺任一项不得继续**。不得创建中间目录、调用子 skill、生成/修改 CSV 或评审。对话中一次性列出全部缺失项并等待用户补齐。

## 中间产物留档

每轮迭代的 CSV 与评审报告**必须**写入中间产物目录，文件名在最终基名上追加后缀 `-epoch-<轮数>`（扩展名前）。

### 命名规则

未指定最终路径时，`{base}` 由可选项拼出：`[<目标仓库>_]<特性名称>特性级集成测试用例` 或 `[<目标仓库>_]<特性名称>DFX测试用例`。用户指定了最终路径则以其文件名（去扩展名）为 `{base}`。

设最终交付基名为 `{base}.csv` / `{base}-评审报告.md`，则：

| 产物 | 中间路径示例 |
|------|----------------|
| 用例 CSV | `{中间目录}/{base}-epoch-1.csv` |
| 评审报告 | `{中间目录}/{base}-评审报告-epoch-1.md` |
| 边界检查报告 | `{中间目录}/{特性基名}-边界检查-epoch-1.md`（FIT+DFX 共用一份；单范围亦写越界检查） |

多范围时分别留档，例如：

- `registry-center_Agent注册特性级集成测试用例-epoch-2.csv`
- `registry-center_Agent注册特性级集成测试用例-评审报告-epoch-2.md`
- `registry-center_Agent注册DFX测试用例-epoch-2.csv`
- `registry-center_Agent注册DFX测试用例-评审报告-epoch-2.md`
- `Agent注册-边界检查-epoch-2.md`

### 目录约定

1. 解析中间目录：用户指定优先；否则 `{项目根}/intermediate`
2. 若不存在则 `mkdir -p` 创建
3. **每一轮**生成/修改完成后立刻写入该轮 CSV；边界检查完成后立刻写入该轮边界检查报告；评审完成后立刻写入该轮报告；禁止只保留最后一轮

### 最终交付文件

闭环结束（通过或满 3 轮）后：

1. 将**最后一轮**通过评审的 CSV（若仍不通过则为 epoch-3 CSV）复制/写入用户指定的最终路径（或默认 `outputs/` 路径），**文件名不含** `epoch-` 后缀；写入后必须执行 `node scripts/ensure-bom.cjs <最终CSV>` 复核 UTF-8 BOM（用写工具重写文件可能丢失 BOM）
2. 同步保留末轮评审报告与边界检查报告到最终路径旁或 `outputs/`，建议命名 `{base}-评审报告.md`、`{特性基名}-边界检查.md`（可另存一份带末轮 `epoch-N` 的中间档以溯源）
3. 对话中列出：各轮中间产物路径、最终 CSV/报告路径、边界检查结论、终止原因（通过 / 满轮次）

## 生成范围与子 Skill 选用

| 用户范围 | epoch 内步骤 1 | epoch 内步骤 2（边界检查） | epoch 内步骤 3 |
|----------|----------------|---------------------------|----------------|
| 仅 FIT | 执行 feature-level-test-cases-gen | 单表越界检查（FIT 混入 DFX） | 评审 FIT CSV |
| 仅 DFX | 执行 dfx-test-cases-gen | 单表越界检查（DFX 复制 FIT）；若用户提供既有 FIT CSV 则一并交叉去重 | 评审 DFX CSV（有既有 FIT 则作为对照） |
| FIT+DFX | 先 FIT 再 DFX（或材料允许时并行，但须各自完整走子 skill） | **交叉检查**两份 CSV：越界 + 重复 | 分别评审两份 CSV；**互传对方 CSV 与本轮边界检查结论** |

- 首次（`epoch=1`）：按子 skill「生成」流程，输出写入 `*-epoch-1.csv`
- 非首次（`epoch≥2`）：以**上一轮 CSV + 上一轮评审报告 + 上一轮边界检查报告**为主要修改输入，连同原始特性材料再次调用对应生成 skill，要求**针对不通过/需整改项修改**（含越界与跨表重复），禁止无视报告重写无关内容；输出写入 `*-epoch-N.csv`

向生成 skill 追加说明（写入调用上下文即可）：

```text
【全流程编排 · epoch-N】
- 模式：首次生成 | 按评审报告修改
- 特性/模块名称：<用户指定，用于 module 列与文件命名>
- 目标仓库：<用户指定或「无」>
- 里程碑：<用户指定或「无」>
- 上一轮用例：<path>
- 上一轮评审报告：<path>（仅修改模式）
- 上一轮边界检查：<path>（仅修改模式）
- 本轮中间输出：<path-with-epoch-N>
- 必须对照 FIT与DFX场景归属判据；禁止越界场景
请严格按本 skill 规范执行；修改模式下优先消除报告「不通过/需整改条目」及边界检查中的越界/重复项。
```

向评审 skill 追加说明：

```text
【全流程编排 · epoch-N】
- 评审文件：<本轮 epoch-N CSV>
- 用例分类：FIT | DFX（与生成范围一致）
- 对照用例 CSV：<对方范围本轮 CSV 或用户提供的既有 FIT；无则写「无」>
- 边界检查结论：<本轮边界检查报告路径>
- 目标里程碑：<用户指定或「未指定」>
- 需求材料：<路径或无>
- 本轮报告输出：<path-with-epoch-N>
评审须将场景归属越界与跨表重复纳入必须项不通过。
```

## FIT/DFX 边界检查与去重（每轮必做）

生成（或修改）CSV 写入后、调用评审**之前**，必须执行本步骤。规则以 [references/FIT与DFX场景归属判据.md](references/FIT与DFX场景归属判据.md) §1、§4、§6 为准。

### 检查内容

| 检查项 | 何时做 | 判定 |
|--------|--------|------|
| **越界** | 凡本轮产出的每一份 CSV | FIT 行验证目标属 DFX（kill 进程/停止容器自愈、资源不足降级、依赖故障恢复、探针/日志/指标/性能/安全/兼容专项）→ 越界；DFX 行以业务结果为唯一断言（主路径走通、功能配置生效、业务负例拒绝且无非功能断言）→ 越界 |
| **跨表重复** | FIT+DFX；或仅 DFX 且用户提供了既有 FIT | 触发操作相同（或同义）**且**断言焦点相同 → 重复。触发相似但断言分属业务 vs 非功能 → 合法并存，不算重复 |

### 边界检查报告（写入中间目录）

```markdown
# FIT/DFX 边界检查 · epoch-N

- 对照判据：skills/test-cases-generator/references/FIT与DFX场景归属判据.md
- FIT CSV：<path 或无>
- DFX CSV：<path 或无>
- 结论：通过 / 不通过
- 越界：<无 | 编号列表 + 应归属>
- 跨表重复：<无 | FIT编号 ↔ DFX编号 + 相同断言焦点>
- 合法并存：<可选列出，不构成不通过>
```

存在任意越界或重复 → 本步结论为**不通过**；对应范围在本轮判定中不得标为通过。修改轮次须优先改归属或删除重复，使断言焦点回到所属表。

## 通过 / 不通过判定

读取本轮评审报告 **§6 统计与结论**（及 §2 模板与文件级结论），并叠加本轮**边界检查**结论：

| 结论语义 | 判定 | 动作 |
|----------|------|------|
| 可交付；或「不通过」计数为 0 且模板符合；**且**边界检查无越界/重复 | **通过** | 该范围结束；FIT+DFX 时另一范围未通过则仅继续未通过范围 |
| 需修改后复审 / 模板不合规 / 存在必须项不通过 / **边界检查存在越界或跨表重复** | **不通过** | `epoch < 3` 则进入下一轮修改；`epoch = 3` 则终止 |
| 仅有「通过但有建议」、无必须项失败、边界检查通过 | **通过** | 建议项可选在下一轮消化，但**不强制**再开一轮；已通过则结束该范围 |

FIT+DFX：**两个范围均通过**（或已满 3 轮）才结束全流程。某一范围已通过则后续 epoch **不再重跑**该范围，只迭代仍失败的范围；已通过范围的中间档保留，最终交付用其最后通过轮次的 CSV。边界检查发现的跨表重复视为**两个范围均未通过**（除非重复对中仅一侧越界且另一侧归属正确，则只迭代越界侧）。

## 执行指令（模型）

1. **确认输入**：核对这些必填项均已由用户给出：特性材料（至少一项）、生成范围（未明示时可推断，无法推断则询问）、特性/模块名称。**缺任一项则停止**，一次性列出待补项；不得创建目录、调用子 skill 或写文件。可选字段（目标仓库、里程碑、既有 FIT CSV、最终路径、中间目录、评审用需求材料）未给则按下文默认或留空。
2. **准备目录**：创建中间产物目录（默认 `{项目根}/intermediate`）。
3. **初始化** `epoch = 1`；记录待处理范围集合（FIT / DFX）。**先读** [references/FIT与DFX场景归属判据.md](references/FIT与DFX场景归属判据.md)。
4. **循环**（`epoch ≤ 3` 且仍有未通过范围）：
   1. 对每个未通过范围：Read 对应生成 skill → 按首次或修改模式生成/修改 → **立即**写入 `{base}-epoch-{epoch}.csv` → **立即**执行 `node scripts/ensure-bom.cjs <本轮CSV>` 确保 UTF-8 BOM（脚本位于本 skill `scripts/`；子 skill 也会执行各自副本，重复执行幂等无害）
   2. **边界检查**：对照归属判据检查本轮 CSV（FIT+DFX 做交叉去重；单范围做越界；仅 DFX 且有既有 FIT 时交叉去重）→ **立即**写入 `{特性基名}-边界检查-epoch-{epoch}.md`
   3. 对每个本轮产出的 CSV：Read 评审 skill → 传入对照 CSV 与边界检查结论 → 评审 → **立即**写入 `{base}-评审报告-epoch-{epoch}.md`
   4. 按上文判定更新各范围通过状态（评审必须项 **与** 边界检查均须通过）；若全部通过则跳出；否则 `epoch += 1`，满 3 轮则跳出
5. **最终交付**：写入无 `epoch-` 后缀的最终 CSV（及评审报告、边界检查报告）；汇总全流程摘要。
6. **对话回复**：范围、轮次、每轮通过与否、边界检查结果、中间/最终路径、终止原因；勿粘贴报告全文。

## 全流程摘要模板（对话末尾）

```markdown
## 全流程摘要
- 生成范围：FIT / DFX / FIT+DFX
- 实际轮次：N / 3
- 终止原因：评审通过 | 已达最大轮次（仍有不通过）
- 边界检查：通过 / 不通过（越界 N 条、跨表重复 M 对；合法并存不计入不通过）
- 边界检查报告：<path>
- 中间目录：<path>
- 各轮产物：
  - epoch-1: <csv>, <报告>, <边界检查> …
  - epoch-2: …
- 最终交付：<csv 路径>, <报告路径>
- 子 skill：feature-level-test-cases-gen / dfx-test-cases-gen / test-cases-reviewer
- 归属判据：references/FIT与DFX场景归属判据.md
```

## 质量自检

- [ ] 每轮 CSV 与最终交付 CSV 均为 UTF-8 带 BOM（`scripts/ensure-bom.cjs` 结果为 `[OK]`）
- [ ] 必填项（特性材料、生成范围、特性/模块名称）均已由用户给出后再执行；缺失未开跑
- [ ] 已按范围完整执行对应生成 skill（含其强制 reference 与归属判据），未手写绕过
- [ ] 每轮在评审前已做 FIT/DFX 边界检查（越界 + 适用时的跨表去重），报告已写入中间目录
- [ ] 评审已传入对照 CSV 与边界检查结论；越界/重复已纳入通过/不通过
- [ ] 每轮产出均已评审，且评审走 test-cases-reviewer（含其强制 reference）
- [ ] 轮次 ≤ 3；第 3 轮后已终止
- [ ] 每轮 CSV、边界检查报告与评审报告均已写入中间目录，文件名含 `-epoch-<N>`
- [ ] 修改轮次以评审报告必须项与边界检查越界/重复为修改依据；必填元数据已透传且未留空；可选元数据未指定则仍留空、未推断占位
- [ ] 最终文件无 `epoch-` 后缀；对话含全流程摘要（含边界检查结果）与路径声明
